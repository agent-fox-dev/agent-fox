# 11. Import afspec from the spec module

**Status:** accepted
**Date:** 2026-10-14
**Supersedes:** the part of [ADR 10](10-move-the-spec-tool-to-its-own-repository.md) that kept `afspec` here
**Related:** [ADR 01](01-adopt-spec-format-v2.md)

## Context

ADR 10 moved the `spec` tool to [`agent-fox-dev/spec`](https://github.com/agent-fox-dev/spec)
and kept `afspec` in this repository, because `impl` reads the packages `spec`
writes. The spec module carries its own `afspec`, the one `spec` writes
packages with. Two copies of the format library drift: a rule added to one
validates packages the other rejects, and the copy of the JSON Schemas here
had to be synced and regenerated by hand (`make json-gen`).

## Decision

`afspec/` is deleted from this repository. Every package that used it imports
`github.com/agent-fox-dev/spec/afspec` instead, and `go.mod` requires the
`github.com/agent-fox-dev/spec` module. The schema copies, the `make json-gen`
target, the v1 migration (`afspec.Migrate` and `afspec/legacy`, which nothing
outside the package used) and the library's own fixtures under `testdata/`
go with it.

## Consequences

**One library writes and reads a package.** `spec` and `impl` validate with
the same code, so a package `spec` reports valid is one `impl` accepts.

**A format change reaches this repository as a dependency update.** It lands
in `agent-fox-dev/spec`, and `go get github.com/agent-fox-dev/spec@<version>`
picks it up here; `make check` then shows what it broke.

**The module is required at a pseudo-version.** The spec module's tagged
releases predate its Go module, so `go.mod` names a commit on its `main`
branch until a tagged release carries the module.
